# 本项目功能演示：知识导入、分块与来源定位

这是一篇供本机功能演示使用的说明文档，内容介绍当前仓库已经实现的能力。它不是某家真实企业的产品政策，也不是收费说明、服务承诺或认证材料。演示中的组织名称、人员名称与工单内容用于学习和验收，不能当成实际客户资料。导入此文档的目的，是观察文本如何保存为版本、如何分成多个段落，以及检索结果如何回到原始文档的位置。

## 文档导入与组织范围

当前独立服务台提供知识库页面。登录用户可以查看所属组织的文档目录和资料原文；文档导入入口只向管理员提供。管理员选择本机的文本文件，填写标题和来源说明，再点击确认并导入。上传接口接受以 UTF-8 编码的 Markdown 或纯文本文件，文件大小上限为一 MiB。这里的 Markdown 文件按文本处理，页面不会把其中的标签渲染为可执行网页，也不会根据来源说明自动访问外部网站。

导入文件时使用当前已认证账号的真实组织。表单没有指定任意组织的授权入口，也不能通过工具凭证代替浏览器会话完成导入。上传操作需要有效的浏览器登录会话和表单确认凭证。服务在写入文档前再次读取账号状态、角色、组织和会话是否有效，所以先前打开的表单不保证之后仍具有写入权限。普通员工能够阅读本组织的文档，但不能使用同一个上传入口添加资料。

## 文件名、内容与版本

同一组织内的同名文件对应同一份导入文档。内容、标题和来源均相同时，重复导入复用当前版本，不重复创建文档。文件内容或者相关元数据发生变化时，系统增加版本并保留此前版本。不同组织使用相同文件名时，仍会得到各自独立的文档。文件名用于识别资料，不会作为任意本机路径读取，也不会触发网络下载。

每个版本保存自己的完整文本、标题、来源说明以及内容摘要。当前检索使用文档的当前版本，原文页面允许有权读者查看保留的历史版本。引用中包含版本号，因此文档更新之后，先前结果仍能指向当时使用的证据。阅读旧版本时应注意版本标记，不能把旧内容误当作当前操作说明；遇到版本差异，应结合实际问题核对哪份资料适用。

## 文档分块与行号定位

较长的文本会按照标题、段落和长度分成多个块，相邻块保留一段重叠内容，以减少上下文在边界处被截断的问题。分块保存的是原文中的实际子串，不由模型重新概括。每个块具有文档编号、版本、块编号、起止字符偏移和起止行号。字符区间使用左闭右开的方式，例如起点为零而终点为十时，对应原文最前面的十个字符。

来源页面按行显示原始文本，并为每个分块设置内部定位标记。检索结果中的来源链接包含固定版本和块编号，点击后可以查看对应的原始段落。核对时先确认版本，再看起止行号，最后检查该段落是否真正支持回答中的事实。定位信息用于追溯证据，不表示该段文字本身经过了人工内容认证，也不表示只要检索分数较高就必然可以回答用户的全部问题。

## 检索与证据不足

当前本机检索使用轻量的词项匹配和排序，不需要下载大规模本地模型。中文文本使用双字词项，英文术语和编号作为完整词项参与匹配。工具返回相关段落、来源位置以及证据状态。问题过于笼统时，适合先补充具体功能、错误提示和发生时的操作；资料缺少所问事实时，应明确说明缺少依据。检索命中某份相关文档，不能自动证明其中包含价格、证书编号、处理时限或未来计划等未记录的信息。

知识资料与工单处理是不同的业务对象。阅读文档不会创建工单，也不会修改已有工单的状态、负责人或处理历史。需要人工跟进时，可以根据用户提供的事实整理工单草稿；正式创建和变更依然走独立确认流程。演示中的知识导入操作本身不会操作这些工单表。本次文档演示会比较工单、草稿、更新提案和事件表的前后摘要，确认导入与来源阅读没有改变已有业务记录。

## 如何观察本次演示

可以先打开此文档的版本一，观察标题、行号和分块列表，再查看版本二中的附加说明。随后用普通员工账号检索“知识导入演示的文档分块和行号定位”，打开返回的固定版本来源链接，检查显示的内容是否与实际原文一致。最后尝试以普通员工身份访问导入接口，应看到权限拒绝结果。其他组织的账号即使知道这份文档的编号，也不能读取本组织的证据段落。

本文只说明代码当前具备的演示能力，不宣称完成生产容量测试、多人统一身份接入、外部企业工单系统集成或合规认证。正常聊天中的工具凭证仍由本机配置确定，服务台网页登录身份与聊天工具身份分别管理。真实多人身份联动属于后续工作，需要通过明确的身份映射与授权设计完成，不能从网页切换账号推断聊天工具的身份已同步改变。
