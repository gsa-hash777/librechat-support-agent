本手册及其中全部流程、角色安排、期限和数值，均为本项目自编的模拟业务资料，不代表真实公司的制度、服务承诺或法律与财税规定，也不表示本机 LibreChat 或客服工具已经实现这些业务功能。

资料用于知识检索与证据定位实验，面向虚构的 demo 组织。它补充独立业务场景，不替换原有 KB-001 至 KB-016，不修改原资料、旧评测题或历史结果。下列正文逐字来自 supplement.json，仅增加标题和来源标记；尚未经真实企业业务负责人验收。

业务资料中的审批、停用、交付等动作需要对应业务人员在适用系统中核实办理；本手册的描述不证明任何动作已经发生。未写明的价格、时限、渠道或能力不能由相近条目推出。

## KB-017 员工离职交接与资料接管

来源：项目自编模拟业务规范 / 补充手册 / 员工离职交接与资料接管

本节为星桥云办公的模拟离职交接规范，适用于同一组织内即将离职的员工、直属负责人和组织管理员。负责人先核对最后工作日、本人负责的项目与待交接资料，形成一份交接清单。清单按项目记录原负责人、接收人和资料所在位置，个人生活文件不列入组织业务交接；同名项目须补充项目编号，不能只凭标题指定接收人。

接收人应逐项检查文件能否打开、版本是否为当前稿、待办说明是否完整，并在清单中确认接收。负责人核对通过后，由组织管理员办理账号停用和必要的资料负责人变更。模拟流程要求在最后工作日前至少2个工作日发起清单核对，但这只是准备要求，不是客服处理时限；离职时间临时提前时需标明未完成项。

账号应停用的时间已经到达时，不能因为交接尚未完成而继续保留离职人员访问权限。管理员应先停用账号，再与业务负责人安排资料接管。接管不等于删除原有修改记录，也不自动授予接收人组织管理员身份。客服可以说明清单字段和排查资料可见性，不能代员工签署交接确认，亦不能承诺停用账号会永久删除其全部业务记录。

## KB-018 外部协作者访问到期与续期

来源：项目自编模拟业务规范 / 补充手册 / 外部协作者访问到期与续期

本节模拟外部顾问参与项目资料审阅的流程，适用于已有项目协作授权的组织成员和外部协作者。项目负责人应记录协作者所属单位、审阅目的、资料范围和截止日期；这里只讨论资料访问期限，不改变成员邀请链接的有效期。外部协作者反馈无法查看时，先区分访问已到期、尚未获得目标资料授权和使用了错误组织三种情况。

模拟规范中，单次外部审阅授权最长7个自然日。需要延长时，由项目负责人说明剩余工作和新的截止日期，再交组织管理员确认；提交续期申请本身不会使过期访问恢复。管理员核对资料所有者意见和协作者身份后才调整期限。排查记录应包含项目编号、授权对象和到期时间，不能把其他成员正常打开页面当作此人的授权证明。

资料审阅只包含已经确认的范围，不意味着协作者可以再邀请他人或查看整个组织。续期不能自动升级为编辑权限，也不能据此修改计费设置。访问到期会终止后续的受控查看，但不能证明对方此前保存的文件副本已经被删除。对副本处置存在要求时，需由项目负责人另行取得对方确认；本资料未提供自动远程删除对方文件的机制。

## KB-019 团队合并时的项目归属核对

来源：项目自编模拟业务规范 / 补充手册 / 团队合并时的项目归属核对

本节为同一组织内部团队调整的模拟工作规范，适用于两个团队合并或项目从一个团队移交到另一个团队。部门名称变化不等于资料已经完成迁移。发起人应先提供原团队、新团队、涉及项目编号和预期生效日期，确认这是同一组织内的归属调整；如果实际涉及两个独立组织，应停止套用此流程并重新确定资料交付安排。

业务负责人建立项目对照表，每个项目至少记录现负责人、拟接收负责人和当前访问成员三项信息。对照表确认后，先选择1个非关键项目试点，由组织管理员核对成员范围并调整归属，再由接收团队核验资料可见性和待办责任。试点核对没有完成前，不应整批变更其余项目；发现同名项目时使用项目编号核对，不能合并名称相似的项目记录。

团队归属调整不应把原本受限的资料自动公开给新团队全部成员。资料所有者需要逐项确认分享范围，管理员只按确认后的范围办理。原团队负责人离岗时，交接与账号停用应分别记录，不能用改团队名称代替人员交接。此模拟流程不包含跨组织复制、自动撤销历史下载或订阅席位合并，也没有给出全部项目调整完成的固定耗时。

## KB-020 多人编辑冲突与内容合并

来源：项目自编模拟业务规范 / 补充手册 / 多人编辑冲突与内容合并

本节描述模拟协作文档的内容冲突处理，适用于两位以上有编辑权限的成员修改同一份业务资料。出现版本冲突提示、正文被其他修改覆盖或同一段存在两种结论时，先暂停继续覆盖保存。排查时记录文档编号、冲突段落、两位编辑者各自开始修改的时间，以及各自依据的版本；单纯页面显示不同不能直接判断另一位成员删除了内容。

处理人先保存双方尚未提交的文字副本，再由资料负责人比较共同起点、甲方修改和乙方修改这3份内容。相互独立的段落可以合并；同一数值、结论或适用条件发生冲突时，应向业务负责人核实后再决定采用哪一项。合并稿需要标明采纳与舍弃的内容，由两位编辑者复核，确认后以一份完整的新稿提交，避免轮流覆盖同一段落。

保存临时副本仅用于防止遗漏，不表示合并稿已经发布。不能把最新提交时间作为内容一定正确的证据，也不能只保留字数更多的一版。若没有共同起点版本，应明确记录比较依据不足，请负责人补充资料；本节不承诺能够找回所有历史修改。客服可协助整理冲突位置，不能代替资料负责人判断两份业务结论哪一个真实有效。

## KB-021 业务审批退回与代理安排

来源：项目自编模拟业务规范 / 补充手册 / 业务审批退回与代理安排

本节是项目采购申请的模拟审批流程，适用于申请人、业务审批负责人和经授权的代理审批人，不适用于客服工单的状态变更或草稿确认。申请被退回时，申请人先读取退回理由，核对被指出的用途、预算项目或附件缺项。退回表示当前提交需要修改，不等于审批人已经同意采购，也不能把退回记录删除后重新标记为已批准。

申请人修改材料后，使用同一申请编号提交修订稿，并说明改动项，保留上一版与退回意见供审批人比较。原审批人休假时，业务负责人应提出代理人、适用申请范围和起止日期，由组织管理员核对安排；模拟规范要求代理期限最长10个工作日。代理关系确认前，申请仍等待原有流程处理，申请人不能自行选择一名同事代为通过。

代理人不得审批自己作为申请人提交的事项；遇到这种情况需交由业务负责人重新指定有资格的审批人。代理结束不会撤销代理期间已合法形成的意见，但后续新的审批需要重新确认授权。审批通过只代表申请获准进入后续采购环节，不表示已付款或已收到货物。本资料没有规定审批多久必然完成，也未规定任何金额可以免去审批。

## KB-022 差旅报销材料补正与重复申报

来源：项目自编模拟业务规范 / 补充手册 / 差旅报销材料补正与重复申报

本节为项目自编的差旅报销资料核对规范，适用于已经结束出差、准备提交费用材料的员工和内部报销经办人，不代表真实公司的财务制度或税务要求。申请人应整理出差事由、起止日期、费用发生日期、费用类别及对应凭证。只有行程截图而没有费用说明时，经办人需先确认截图对应哪笔支出，不能按截图总额直接认定可报销金额。

模拟流程要求员工在返程后5个工作日内提交材料核对；这一期限不是付款承诺。经办人按费用发生日期、金额和凭证编号检查重复项，再核对行程与支出的对应关系。同一笔支出多人分摊时，分别说明分摊依据和本人申报部分，并关联同一业务事项。缺少凭证时应标记为待补正，写明所缺材料，由申请人补充后重新核对。

材料齐全只是进入内部审核的条件，不代表所有费用都已获批。已由组织统一支付的支出不得再作为员工个人垫付款重复申报；重复上传同一凭证也不能形成两笔可报销费用。超过模拟提交期限的材料应说明原因交经办人处理，不能自行改动费用日期。本资料不提供报销额度、可抵扣税额或到账时间，遇到这些问题应核对适用的正式制度。

## KB-023 办公设备采购与分批验收

来源：项目自编模拟业务规范 / 补充手册 / 办公设备采购与分批验收

本节模拟项目团队采购办公设备后的接收流程，适用于采购申请人、收货经办人和资产保管人。收货前应核对采购申请编号、设备品类、约定数量及交付地点；货物已到达前台只表示已收取包裹，不表示设备验收合格。包裹外观异常时，先记录外观和运单信息，再通知采购经办人确认后续处理，不要在验收记录中填写一切正常。

开箱后，收货经办人逐项核对型号、数量和可见配件，资产保管人检查设备标识及基础通电情况。模拟规范要求验收清单至少由收货经办人和资产保管人2个角色核对，不能仅凭申请人一句已收到就结项。分批交付时，每批记录实到数量、缺件情况和已验收数量，并关联原采购申请，剩余数量继续保持待交付状态。

发现少件、型号不符或无法正常通电，应记录具体异常并交采购经办人联系供货方处理；异常设备不应直接登记为可领用资产。验收记录通过不等于采购款已经支付，也不自动同意额外采购。返修或换货是否发生费用需依据对应采购约定，本模拟资料没有规定统一赔偿金额、保修期限或补货时限，不能据此向申请人作出承诺。

## KB-024 会议室重复预约与占用核验

来源：项目自编模拟业务规范 / 补充手册 / 会议室重复预约与占用核验

本节是组织内部会议室使用的模拟规范，适用于会议组织者、参会成员和会议室管理员。发现两场会议显示在同一时间段，先核对会议室编号、所在楼层、开始与结束时间，以及双方使用的时区。名称相似的会议室可能属于不同楼层；个人日历中的会议邀请也不一定已经取得房间预约，不能只根据邀请标题要求另一场会议离开。

模拟规则规定单次会议室预约最长2小时，确需延长时应先核对后续时段是否空闲，再向会议室管理员说明用途。会议开始后10分钟仍无人到场，只构成管理员核查的条件；管理员联系组织者并现场确认未使用后，才可取消该次房间占用。参会者不能仅凭门外暂时无人就自行认定房间已释放，也不能擅自替他人延长预约。

确认为重复预约时，管理员核对有效预约记录，协调其中一方更换空闲房间或调整时间，并通知两场会议组织者。取消房间预约不等于取消日历会议或视频会议，组织者应另外通知参会人。连续多日的固定会议需要分别检查各次实际安排。本资料未规定迟到自动扣费、会议优先级或所有会议室都配有视频设备，不能从空闲状态推断这些事项。

## KB-025 任务通知未收到与免打扰检查

来源：项目自编模拟业务规范 / 补充手册 / 任务通知未收到与免打扰检查

本节描述模拟业务任务的通知排查，适用于已经被分配任务、但未注意到提醒的组织成员。先核对任务编号、接收成员、触发动作与发生时间，再确认问题是任务列表看不到，还是任务已存在但没有邮件或移动提醒。前者应检查组织和任务访问范围；后者再检查个人通知设置。发送者看到提交成功并不能证明接收者已经读到通知。

模拟规范把任务状态页作为处理依据，通知只用于提示。排查提醒缺失时，先核对任务是否确实指派给本人，再检查对应渠道是否启用、是否处于免打扰时段，以及终端是否允许通知。演示中的默认免打扰窗口为每日22时至次日8时，使用成员个人设置的时区；成员修改过窗口时应以当前设置为准，不能直接套用默认时间。

免打扰不会取消任务或延长任务截止日期。紧急协作应由业务负责人确认接收人已经获知，而不是连续重复创建相同任务来催促。收集排查材料时只需要任务编号、渠道类型、设置截图和发生时间，截图应遮挡无关个人信息。本节没有承诺通知必达、固定发送延迟或对方必须在多久内回复；资料也不足以证明未读提醒就是邮件系统故障。

## KB-026 离线编辑与重新联网后的同步核对

来源：项目自编模拟业务规范 / 补充手册 / 离线编辑与重新联网后的同步核对

本节为模拟移动办公中的离线文字编辑规范，适用于断网期间保留了待同步草稿的成员。恢复网络后发现另一台设备没有新内容，应先核对账号、组织、文档编号及两台设备显示的保存状态。离线草稿只表示设备保留了编辑内容，不等于服务器已经接收，也不表示其他协作者已经看到；不能因为本机能显示文字就宣布同步成功。

处理前先把未同步文字保存到本人获准使用的位置，避免排查过程中丢失。随后确认网络可用，查看待同步项，再与服务端当前版本比较。模拟流程建议先处理1份非关键草稿，核对服务端内容和另一台设备显示一致后，再继续处理剩余项。若服务端已经存在其他人的新修改，应按内容冲突流程核对差异，不能直接用离线稿覆盖。

在所有待同步项得到核对之前，不应清除应用数据、退出并删除本地缓存或卸载客户端。暂存文字也不应传给无权访问该资料的人。看到失败提示时记录设备类型、客户端版本、发生时间和草稿编号供排查，避免在工单附上整份业务正文。本资料没有离线草稿永久保存的保证，也没有承诺断网持续任意时长后都能自动合并全部修改。

## KB-027 业务记录批量登记与校验报告

来源：项目自编模拟业务规范 / 补充手册 / 业务记录批量登记与校验报告

本节是模拟项目台账的批量登记规范，适用于得到台账维护授权的业务经办人，不是本机知识库上传格式的功能说明。登记前应核对目标组织、台账名称和字段含义，为每条记录准备业务编号、名称、负责人及发生日期。业务编号用于识别同一业务事项，不能因为名称相同就合并，也不能把人员显示名称当作稳定的负责人编号。

首次批量登记时，模拟规范要求先用不超过20条记录核对映射，再处理其余数据。经办人先运行校验，检查必填字段、日期格式和重复业务编号；校验报告中的通过只表示该行符合登记条件，不代表数据已经写入。确认字段映射和待登记数量后，才执行提交，并记录本次批次编号，随后抽查业务编号与负责人是否对应。

同一文件出现重复业务编号时，应先由业务负责人确认是重复行还是同一事项的不同阶段，再整理成符合台账要求的记录。已经存在的业务编号不能默认覆盖，应先确认是补充信息还是需要更正原记录。部分行失败时保留成功与失败清单，仅在核对结果后补交失败项，避免把全量数据再次登记。本资料未定义可支持的全部文件格式或最大台账规模。

## KB-028 项目汇总报表与明细数量差异

来源：项目自编模拟业务规范 / 补充手册 / 项目汇总报表与明细数量差异

本节为模拟项目运营报表的核对规范，适用于需要比较汇总数字与台账明细的业务负责人。发现报表总数与自行相加不一致时，先记录报表名称、统计日期、目标项目、筛选条件和数据截止时点。不同范围或不同截止时点的结果不能直接比较；看到汇总数字较小，也不能据此认定某些业务记录已经被删除。

模拟报表中的已完成事项数按完成日期归属统计周期，新增事项数按创建日期归属统计周期，两者不是同一口径。跨月创建并完成的事项可能分属不同月份。核对时先选择1个具体项目，使用相同周期和状态范围导出有权访问的明细，去掉重复业务编号后再与汇总比较；撤销的事项不计入已完成事项数，但原记录仍可在相应状态范围内核对。

汇总只反映当前账号可访问的数据，因此不同成员看到的数字可能不同。空白单元格表示该项未形成统计值，不能直接按零解释；明确显示零才表示在所选范围内没有符合口径的事项。若核对后仍有差异，应提交项目编号、两边筛选条件、截止时点和差异样例。本资料未承诺报表实时更新，也未提供统一刷新间隔或历史数据回补时限。

## KB-029 项目归档与模板复用边界

来源：项目自编模拟业务规范 / 补充手册 / 项目归档与模板复用边界

本节为已结束业务项目的模拟归档规范，适用于项目负责人、资料所有者和组织管理员。归档前先核对是否仍有未完成事项、待补材料或未确认的交接记录，并整理最终说明。项目负责人应列出需保留的成果与允许继续查看的成员范围，由资料所有者确认后交管理员办理；项目已到计划结束日，并不自动说明这些检查已经完成。

模拟流程将归档项目作为只读业务记录保留，原有资料仍按确认后的范围查看。若后续需要修订归档资料，由项目负责人说明修订原因、涉及内容与责任人，交组织管理员确认后再安排处理。需要发起类似项目时可以申请复用业务模板，但应重新填写项目名称、负责人、起止日期及成员范围，逐项核对模板中的旧客户或旧事项信息。

归档不等于删除，不能把归档操作当作清除历史记录的证明。模板复用只复制已获准复用的结构或说明，不自动复制原项目成员权限、审批结果和已完成状态。未经资料所有者确认，不应将原项目业务内容带入新项目。本资料没有规定归档记录会在固定年限后自动销毁，也没有承诺归档后所有外部副本都能被收回。

## KB-030 同名成员选择与目录信息核对

来源：项目自编模拟业务规范 / 补充手册 / 同名成员选择与目录信息核对

本节描述模拟组织通讯目录的身份核对流程，适用于任务分配人、资料分享人和维护成员资料的管理员。搜索出现两个同名成员时，应先核对当前组织，再比较成员编号、所属团队和账号状态；头像或显示名称相同不能证明是同一个账号。已经停用的旧账号与新加入的同名成员应分别处理，不能把旧账号的业务责任直接移给新成员。

模拟规范要求选择负责人或分享对象前，至少核对成员编号与所属团队这2项信息；仍有疑问时，请业务负责人确认对应关系。目录团队名称明显过期时，应由成员向组织管理员提交更正申请，说明正确团队及相关业务依据。管理员核对后修改展示信息，再检查受影响的任务指派，不能只凭别人转述的昵称批量替换所有负责人。

更改显示名称或团队标签不会改变稳定的成员编号，也不自动授予新团队的资料访问权限。发现资料可能分享给了错误同名成员，应立即请资料所有者检查实际分享对象和访问范围，再安排纠正，不要先向两人都发送完整资料试探身份。本资料不支持通过陌生人的联系方式推断其内部身份，也没有规定个人改名会自动迁移其他账号的数据。

## KB-031 业务附件外发前的审阅与脱敏

来源：项目自编模拟业务规范 / 补充手册 / 业务附件外发前的审阅与脱敏

本节为模拟项目资料对外提交的审阅规范，适用于需要把业务附件交付给合作方的项目成员和资料所有者。发起人应说明接收单位、业务目的、拟发送资料及必要内容，先确认自己有权申请外发；能在组织内查看文件不等于已经获准向外部发送。外发清单应区分最终成果与工作底稿，不能把整个项目目录作为默认交付范围。

资料所有者逐项核对外发范围，检查正文、批注、隐藏表格和附件中的无关信息，制作经审阅的交付副本。模拟规范要求发送前由制作人和另一名复核人共同核对接收对象、文件版本及脱敏结果。发送后记录交付时间、文件清单与接收确认；如果复核时发现敏感内容，应先修正副本并重新检查，不能把打码后的截图当作原文件已经脱敏的证明。

脱敏副本通过审阅不代表原文件可以公开，正文中删除的字段也可能仍存在于批注或工作底稿中。外发结果只针对本次用途和接收方，不自动允许对方再次转发。发生误发时，应先报告项目负责人，记录误发对象和范围并请求对方停止使用、删除副本。本资料没有自动撤回任意外部文件的保证，也不提供真实企业的保密等级或法律结论。

## KB-032 现场照片材料的清晰度与补拍

来源：项目自编模拟业务规范 / 补充手册 / 现场照片材料的清晰度与补拍

本节为模拟设备现场问题收集照片的业务规范，适用于提供故障材料的成员和负责初步核对的经办人。拍摄前应明确要说明的是设备外观、屏幕提示还是连接位置，并记录设备业务编号与拍摄时间。照片缺少目标对象、重要文字被反光遮挡或只显示局部画面时，经办人应指出具体缺项，不能靠猜测补全型号或错误内容。

模拟规范建议照片长边至少1200像素，先拍一张包含设备与环境关系的整体照片，再补拍能看清问题位置的近照。像素数量只是建议，不代表必然清晰；提交前应放大检查关键文字是否可读、连接口是否在画面内。若涉及多台设备，应分别注明各自编号，避免把一台设备的外观与另一台设备的屏幕提示作为同一问题材料。

拍摄范围应避开无关人员、客户资料和可见凭据，只保留排障所需部分。需要补拍时保留原材料的对应关系，说明新照片替换了哪一项，不要把补拍当作问题已经修复。客服能够根据可辨认的现象提出下一步核对建议，但照片不足以独立确认所有硬件故障。本资料未承诺自动识别每一种错误提示，也未规定提供照片后多久必然完成维修。
